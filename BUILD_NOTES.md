## 2. Design plan

### Pass 1 (first instinct)
- Colours: `#0A0A0A` bg, `#141414` surface, `#262626` border, `#EDEDED` text, `#A1A1A1` muted, `#3B82F6` electric-blue accent.
- Type: Geist + JetBrains Mono.
- Layout: big-name hero, bento skills, one card grid for all 11 projects, timeline, contact.
- Signature: Shiksha pipeline diagram. Motion: hero stagger, reveals, parallax, Lenis.

### Critique
- *Would this be the same for any developer with a dark theme and an accent?* Yes. The palette is the research's example verbatim; Geist + JetBrains Mono is the Vercel-template default pairing.
- One card grid for everything is the "wall of identical rounded cards" tell, and it hides the most specific fact in the material: the AI work has **no imagery but real architecture**, while the web work is **all imagery** (eight live sites with very different visual languages — editorial serif, heavy grotesk, condensed industrial, e-commerce). They need two different exhibit formats.
- The hero said "who", not "what, with evidence". The unusual combination (three deployed AI apps *and* eight live business websites) should be the first thing read, as counts with links, not adjectives.
- Signature choice holds: Shiksha is the one system where both halves meet — LLMs write *animation code* that a *headless browser* renders.

### Pass 2 (revised, adopted)
**Concept — "frame and exhibit."** The site is a quiet, gridded frame; the exhibits carry the colour. Boldness is spent in one place: the Shiksha diagram.

## 4. Motion budget (landing only)

| # | What | How | Why | Budget |
| --- | --- | --- | --- | --- |
| 1 | Hero intro: name lines rise out of masks, then meta / actions / index fade up. The statement and supporting line (the LCP candidates) render immediately | CSS keyframes gated by `html[data-intro="play"]`, set by a tiny inline script before first paint; runs without waiting for hydration | first impression; content is in the HTML from the first frame | ≈0.72 s total, 70 ms line stagger, 60 ms item stagger, 20 px rise; auto-ends at 0.9 s; hard cap 2.5 s |
| 2 | Skip animation | real `<button>`, inline-script listeners (work pre-hydration): click, Enter/Space, Esc, wheel/touch/keyboard scroll | control | instant settle |
| 3 | Section reveals | motion `useInView({ once: true })`; armed only after hydration and only for elements below the fold, so SSR HTML is never hidden | pacing | 500 ms, 70 ms stagger, 16 px |
| 4 | Parallax on the two large website screenshots | `useScroll` + `useTransform` motion values written straight to `style.transform` (no React state, no `m` runtime); the hook-bearing child only mounts for fine pointers without reduced motion | depth on the exhibits | ±3.5 % of frame height, 1.08 scale |
| 5 | Signature pipeline | stage tabs; motion `useInView` starts one autoplay pass; active edges draw with SVG `pathLength="1"` + CSS `stroke-dashoffset` keyframes, then the arrowhead fades in | explains the system | one pass ≈4.2 s (under WCAG 2.2.2's 5 s), no loop; any interaction stops it |
| 6 | Smooth scroll | Lenis, landing only, wheel only; dynamically imported so touch and reduced-motion visitors never download it; anchors use the target's CSS `scroll-margin-top` | front-door feel | lerp 0.14 (closest to native, with inertia) |

Everywhere (functional pages too): CSS hover 150–200 ms, press `scale(.97)` 120 ms, focus rings, "Copied" state, menu open/close. No page transitions.

Deviation notes:
- The brief lists `whileInView` for reveals. Motion serialises `initial` into the server HTML, which would hide below-the-fold content until hydration — hard rule 6 / §10 "JavaScript delayed → key content is still readable" wins. So reveals use `useInView` (same library) armed after mount.
- The brief suggests `LazyMotion` + `domAnimation`. After measuring, nothing on the page needs Motion's animation features: the diagram's line drawing is CSS and parallax writes motion values directly. Not shipping the feature bundle at all is smaller than lazy-loading it. `MotionConfig reducedMotion="user"` stays around the landing tree. With this and the lazy Lenis import, landing first-load JS went from 198 KB to 155 KB gzip.

## 6. Decisions log

- Repo was empty → Next.js 16.3.7 (App Router, Turbopack), React 19.2, TS, Tailwind 4, npm (only package manager installed). No git init (not asked).
- One root layout (`app/layout.tsx`); groups `(landing)` and `(site)` each render skip link + header + footer so the `Skip animation` button can be the first tab stop on `/`.
- Intro is CSS + ~1 KB inline script, not motion: works before hydration, no flash for return visitors, and keeps LCP on real text.
- Internship dates withheld (ambiguous mapping, Q9).
- Uniqform is listed in `data.md` as a role only, so it's in Experience, not in the websites grid.
- Website descriptors come from each site's own title/meta, not invented.
- No PDF supplied → `/resume` offers "Print / save as PDF" (`window.print()` + print stylesheet).
- OG image: static PNG rendered once from an HTML card in the site's fonts (no runtime image generation).
- Icons: lucide for UI glyphs only; social links are text-labelled (no brand icons).
- Command palette: cmdk `Command` inside a native `<dialog>` (showModal gives the top layer, an inert background, Esc and focus return). cmdk's `Command.Dialog` renders no dialog title, so Radix would log an a11y error. showModal focuses cmdk's root (tabindex −1), so the input is focused explicitly. The chunk loads on first open and is prefetched on hover/focus of "Jump to…".
- `experimental.inlineCss`: ~10 KB of Tailwind CSS is inlined into the HTML, so there are no render-blocking requests. Portfolio visitors are mostly first-time visitors, the case the Next docs recommend it for.
- Desktop nav appears at ≥1024 px; below that, "Jump to…" (≥640 px) and a labelled Menu button.
- Reduced-motion detection that changes rendered output uses `useSyncExternalStore` with a server snapshot. Motion's `useReducedMotion` read the real value on the first client render, which caused a hydration mismatch (React #418) and a root re-render that wiped `html[data-intro]`.
- Link prefetching: on functional pages Next prefetches `/` (header link), so landing CSS/JS can be *fetched* there; functional routes never import or execute it.
- Press feedback is CSS (`scale(.97)`, 120 ms, the shared ease) rather than a Motion spring: it meets the brief's numbers on every page without shipping Motion outside the landing group. No layout animations were needed, so no spring token exists.
- Tried and removed: `<Suspense>` boundaries around landing sections to split hydration (no measurable TBT change).
- Source typo fixes, meaning unchanged: "upto 15%" → "up to 15%"; "LLM- backed" → "LLM-backed". The Veridex bullet ends at "…frame-level data." because the trailing fragment "; on a held-out set." carries no claim (Q11).
